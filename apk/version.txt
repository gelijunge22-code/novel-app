# 2.7.4：**根治"每次打开都要重输密码"** + 更新检查不再干等 + 去掉自检面板
#        · 真根因（用户给的关键线索："做大了之后才有的问题"）：老版 App 是**从服务器
#          加载页面**的，登录 cookie 由 WebView 自己保管、重启还在，所以当年不用输密码；
#          新版为了"打开就有界面"改成**从安装包里（file://）加载**，而安卓对 file://
#          页面**不保留 cookie/localStorage** —— 令牌存不住，于是每次都要重输。
#          解法：登录成功时把口令存进手机（SharedPreferences KEY_PW），启动时**静默
#          登录**一次，用户根本看不到登录页。令牌存盘那条路保留（双保险）。
#        · 更新检查：以前 fetch 给 60 秒超时，点一下要干等一分钟、还一句提示都没有
#          （看着像卡死）。改成 **10 秒必回**，查不到就明说"连不上 GitHub，手动更新也行"。
#        · 去掉上一版加的自检面板（用户说没用、还慢）。
# 2.7.5：**根治卡顿** —— JSON 请求不再走"同步桥"，改回异步 fetch
#        · 真凶（跟老版并排比出来的）：老版 App 页面是从**服务器**加载的，前端用
#          `fetch()` 发请求 —— **异步，不挡界面**，所以丝滑。
#          新版改成"内嵌前端"后，为了绕开 file:// 的跨源限制，把所有 JSON 请求
#          塞进了 `NBApp.request()` 这个 Java 桥 —— 而**桥是同步调用**：
#          JS 调 Java 要停下来等 HTTP 发完再回话。公网上一个来回几百毫秒，
#          界面就跟着卡几百毫秒（每次请求都卡一下）。
#          修：JSON 一律走 fetch（WebView 已开跨源 + 服务器给了 CORS），
#          桥只留给"必须同步拿值"的小事（版本号/震动/下载/存口令）。
# 2.7.6：**把 App 里那套 Python 后端整个删掉** —— App 从此是纯前端壳
#        · 包里曾经塞了 Chaquopy（嵌入式 CPython）+ 三种 ABI 的运行时 + 30 多个 wheel：
#          未压缩约 31MB，而真正要用的前端只有 1MB。当年"把后端装进 App"那个方案作废后，
#          行李一直没扔（因为它是**关着**的、不跑就不出错，所以每次都在修别的问题）。
#        · 为什么要删：① 白占 20 多 MB，下载安装都慢；② 留着就永远有"哪天被打开、
#          App 连到自己的空后端、界面看着正常其实什么都没有"的隐患（用户担心的正是这个）。
#        · 怎么删的：Gradle 摘掉 com.chaquo.python 插件与整段 chaquopy{} 配置；
#          但 MainActivity/ApiBridge 里还留着"本机离线后端"的代码路径（默认不执行），
#          直接删要动很多逻辑、风险大 —— 所以在 src/com/chaquo/python/ 放两个**空壳类**
