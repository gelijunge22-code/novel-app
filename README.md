# 写作台

自研后端 + 移动端网页 + 安卓壳。部署在你自己的机器上，稿子只存在你自己那里。

[快速开始](#快速开始) · [功能](#功能) · [手机 App](#手机-app) · [部署到外网](#部署到外网可选) · [许可证](#许可证)

## 这是什么

一套给自己用的长篇写作工具，包含三部分：

- **后端**：Python（FastAPI），管数据、调模型、跑写作流程
- **网页版**：原生 JavaScript，没有构建步骤，浏览器打开就能用
- **安卓壳**：把同一套网页装进 App，连你自己那台服务器

仓库里**不含任何人的书稿、设定或密钥**。clone 下来是空的，从第一本书开始都是你自己的。

## 快速开始

需要 Python 3.11 或更高。

```bash
git clone https://github.com/gelijunge22-code/novel-app.git
cd novel-app

python3 -m venv server/venv
server/venv/bin/pip install -r requirements.txt

server/venv/bin/python -m uvicorn server.app:app --host 127.0.0.1 --port 8899
```

浏览器打开 **http://127.0.0.1:8899/** 就能用了。

### 第一次登录的口令

每台机器**首次启动时随机生成**一个，不会所有人共用一个。按这个顺序取：

1. 启动前设的环境变量 `NOVELAPP_INIT_PASSWORD`（想自己指定就用它）
2. 没设 → 启动时**控制台直接打印**出来
3. 同时也写到 `data/initial-password.txt` 和 `data/口令.txt`（权限 600）

```bash
cat data/口令.txt
```

改口令（立刻生效，不用重启）：

```bash
python3 tools/set_password.py            # 随机生成一个新的
python3 tools/set_password.py 我的新口令   # 设成你要的
```

登录后也能在 App 的「设置」里改。

## 功能

### 写作流程

一场创作可以拆成几棒：出方案 → 逐条挑刺 → 取料查证 → 写正文 → 复审改稿。每一棒是独立的一次模型调用，写手可以放开写，挑刺的会真的挑。

三种干活方式：**讨论 / 计划 / 执行**。每一种都能二选一：

| | 分工 | 一个人 |
|---|---|---|
| 谁来做 | 计划、取料、查证、写作、挑刺各一个 AI | 同一个 AI 从头做到尾 |
| 适合 | 正式写稿、要质量 | 快速改一句、赶时间 |
| 代价 | 慢、费额度 | 少了互相挑刺 |

写正文那一棒会把稿子落盘；讨论和计划这两棒不碰任何文件。

### 模型设置

每个模型的右上角可以打开它自己的参数面板：上下文上限（1M / 256K / 128K 等快选）、单次最大输出、是不是推理模型，还有一个高级参数 JSON，直接并进请求体。改完只影响这一个模型。

### 世界引擎

把人物、势力、门派这些记成带状态的主体，事实和关系存在库里。可以从设定文件一键抽取事实，也可以检测新写的正文跟已有设定有没有冲突。

### 文字检查

内置 568 条中文写作的 AI 味规则（填充词、机械过渡、公式化排比等），成稿直接标出问题句。规则表可以自己改。

### 听书

按段落把稿子念出来，可以边写边听。

### 联网搜索

默认关闭。要用的时候在对话框旁边打开，开了才会发请求，关着一个请求都不发。默认与主创共用同一个模型。

## 手机 App

两种拿法：

**一、从你自己的网页里下**（推荐）

进入写作台 → **设置 → 关于 → 安卓安装包**。下载到的就是你这个实例的 App。

**二、从仓库里拿**

[`app/写作台-通用版.apk`](app/写作台-通用版.apk) 是空白通用版：不含任何书稿，也不含任何服务器地址。

两种包都一样，打开后要**在登录页点「服务器设置」，填你自己那台的地址**，再用你的口令进去。

想从源码自己打包（需要 Android SDK + JDK 17）：

```bash
SEED=0 bash apk/build.sh                               # 空白通用版
SERVER=http://你的地址:8899/ SEED=0 bash apk/build.sh    # 打进去自己的地址
```

## 部署到外网（可选）

前端和接口在同一个端口上，前面挂个反向代理就行。仓库里带了现成的 systemd 服务：

```bash
cp deploy/novelapp.service ~/.config/systemd/user/
systemctl --user enable --now novelapp
```

> **公网一定要自己加一层认证**（Caddy / Nginx 的 basic auth 都行）。
> 不要把没有口令的端口直接暴露出去。

## 数据

```
data/books/<书名>/          正文、设定、角色卡、大纲
data/app.db                 会话、世界引擎的实体与事实、模型配置
data/initial-password.txt   首次启动生成的口令
```

- 全部在本机，`.gitignore` 已排除 `data/`，不会误传到仓库
- 删书先进 `data/trash/`，不直接抹
- 备份 = 把 `data/` 整个目录复制走

## 目录结构

```
server/          后端：路由、引擎、数据层
  routers/       业务接口
  engine/        编排、世界引擎、文字检查、联网搜索、语音
frontend/        网页版（原生 JS + CSS）
apk/             安卓壳
tools/           脚本：改口令、依赖自检、打包校验
deploy/          systemd 服务与反向代理示例
```

后端是 Python，前端是原生 JavaScript，没有构建步骤，改了刷新就生效。
