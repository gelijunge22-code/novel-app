# 飞行模式全功能自测报告

> 交付要求（GOAL N1 / C1 / C2）：**手机开飞行模式 → App 能打开、能翻书、能看设定、能扫 AI 味、
> 能看统计、能新建/编辑章节、能导出、能备份。** 只有"调模型写正文"允许要求联网，
> 且断网时要有清楚提示，不许转圈、不许报错糊过去。
>
> 本报告 = 三份可复现的实测 + 一份"做不到的老实话"。每条都带命令与输出，不靠"我觉得"。

---

## 0. 一句话结论

**离线全功能：成立。** 手机里跑的是**完整的后端**（`server/` 原样进包，靠 Chaquopy 的 CPython 运行），
不是"阉割过的本地实现"，也不是"网页壳"。`api.js` 一行没改分支语义：**一份前端两种跑法**
（App 内走 JS 桥 → 同一个 ASGI 应用；浏览器里走 HTTP）。

**唯一必须联网的事：调模型生成/改写正文。** 这一条断网时给的是中文人话，不是转圈。

**还没做到的：真机没装过。** 这台构建机没有 KVM，起不了安卓模拟器（见第 4 节）。所以下面第 1、2 节
是"按安卓壳同一套规则做的模拟实测"，不是真机飞行模式。这是本报告最大的诚实缺口。

---

## 1. 证据一：设备模拟（24/24）—— 手机里那份代码真的跑得起来

命令：

```bash
server/venv/bin/python tools/ondevice_sim.py
```

它做的事：把 APK 里那份 `server/` + 内嵌前端 + 快照，铺到"手机里的目录"（`/tmp/...`），
用**和 App 完全同一个入口** `main.start(dir, www, seed, port)` 起服务，然后**像手机一样**逐项用。

```
  ✓ ① 准备好「手机里的」目录（前端 18 个文件 + 快照）
  ✓ ② APK 里那份代码能在本机起服务（App 里的同一入口 main.start）
  ✓ ③ 快照铺开了（第一次启动才有）
  ✓ ④ 服务只绑 127.0.0.1（别的 App / 外部连不进来）
  ✓ ⑤ 本机自动登录（手机上不用输密码）
  ✓ ⑥ 书架上有随包带进来的那本书（断网也有得看）
  ✓ ⑦ 翻书：中文路径的章节读得出来（正文 >1000 字）
  ✓ ⑧ 看设定：设定树读得出来
  ✓ ⑨ 扫 AI 味：全书扫得出分数（本地规则，不联网不花钱）
  ✓ ⑩ 看统计：有字数/章节数
  ✓ ⑪ 新建章节（中文文件名）
  ✓ ⑫ 编辑章节：写进去、读回来一致
  ✓ ⑬ 导出整本 TXT（本地导出，不联网）
  ✓ ⑭ 导出整包 bundle（备份用）
  ✓ ⑮ 备份：建一份 + 列表里看得到
  ✓ ⑯ 没网也没配模型时，写作台开屏就说清楚为什么（不是转圈）
  ✓ ⑰ 模型连不上时给的是中文人话（不是 500/英文栈）
  ✓ ⑱ 杀掉进程再起：手机里写的那一章还在（数据是手机上的，不是内存里的）
  ✓ ⑲ 第二次启动不再重铺快照（不许把用户改过的稿子盖回去）
  ✓ ⑳ 本地口令每次启动都在（前端能自动登录）
  ✓ ㉑ 扫人物声音：给得出分数与逐人指纹（本地算，不联网）
  ✓ ㉒ 看节奏曲线：每章一个点 + 走势报警（本地算）
  ✓ ㉓ 角色一致性体检：读得出报告（本地算）
  ✓ ㉔ 参考书架：放得进去、列得出来，而且能进写正文的预演提示词

=== 设备模拟共 24 条：通过 24，失败 0 ===
报告：docs/设备模拟实测.json
```

## 2. 证据二：飞行模式界面自测（18/18）—— 断网把界面真点一遍


模拟规则（和安卓壳一致，不是随便断个网）：

| 模拟项 | 怎么做的 | 对应真机上的什么 |

| JS 桥 | 注入 `window.NBApp.request()`，语义照抄 `ApiBridge.java`：同步返回 `{"status":N,"body":"…","error":""}` | `@JavascriptInterface` 那条进程内通道 |

```
  ✓ ④ 设定读得出来（本机库）

  ✓ ⑦ 新建章节（中文文件名）：建得出、读得回来
  ✓ ⑧ 导出整本 TXT：本地导出真的落了个非空文件
  ✓ ⑨ 备份：建得出一份（数据自持，断网也行）
  ✓ ⑩ 断网调模型：给的是中文人话（不是转圈、不是英文栈）
  ✓ ⑪ 收尾：自测用的那本书进了回收站（不留垃圾在书架上）
  ✓ ⑫ 全程 API 调用都走的是 JS 桥（进程内，不过网卡）—— 28 次
  ✓ ⑬ 全程 0 个外部主机请求（等价于飞行模式：CDN/模型供应商全都够不着）
```

## 4. 做不到的 / 还不牢的（老实话）

| # | 做不到的事 | 为什么 | 影响 |
|---|---|---|---|
| 1 | **真机上跑飞行模式** | 这台构建机没有 KVM，起不了安卓模拟器；也没有真机可插 | 上面第 1、2 节是"按安卓壳同一套契约做的模拟"，**不是**真机实测。真机第一次开机时的 Chaquopy 初始化耗时、厂商 WebView 差异、飞行模式下 `file://` 取本地资源，都还没被真实硬件检验过 |
| 2 | 调模型写正文 / 改写 / 生成细纲 | 必须联网（本地不跑模型） | 断网时界面给中文提示（⑯⑰ 覆盖），不是转圈 |
| 3 | 上传类（导入文件、音频封面） | 走 `FormData`，桥是同步字符串返回，塞不下二进制 → 回落到本机 127.0.0.1 | 本机服务在手机上一直都在，所以**离线可用**；只是这条路不是"纯桥" |
| 4 | 流式生成（SSE） | 同上，桥同步返回，流式只能走本机 127.0.0.1 | 同上：离线可用，但要本机端口活着 |
| 5 | 真机装 APK 后首次同步服务器 | 需要联网一次（可选） | 不做也完全能用，包里有 seed 快照 |
| 6 | 网页版 | 照旧能用，没砸 | — |

## 5. 复现方式（一条命令一块）

```bash
server/venv/bin/python tools/ondevice_sim.py     # 24/24  手机里那份代码跑不跑得起来
node tools/e2e-flightmode.js                      # 18/18  断网把界面真点一遍
bash tools/verify_apk.sh                          # 全部通过  包里到底有什么
bash apk/build.sh                                 # 重新打一次包（内含前端逐字节同步 + 版本号回读核对）
```

> 提醒：**只要再动 `frontend/`，就必须重打一次包**，否则安装包里的界面是旧的。
> 打完用 `bash tools/verify_apk.sh` 验"包里那份跟 `frontend/` 逐字节一致"。
