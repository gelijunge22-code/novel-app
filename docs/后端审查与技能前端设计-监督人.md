## 二、用户说的"很空、有没有都一样" —— 三个真原因

### 原因 1：**入口太多、太碎，每个都薄**
28 个入口摊在手机上，每个点进去只有一两屏。用户记不住、也看不出差异。
→ **该合并的合并**（见第五节）。

### 原因 2：**后端"有接口"但前端只显示一个列表**
例如：世界引擎后端有 36 个接口（实体/别名/事实/关系/时刻/时间线），
前端多数只做到"列出条目"。**能力在，但没被"用起来"**。

### 原因 3：**前后端都没把"它对写作帮了什么"说清楚**
每个技能缺一句**人话**："这个东西在什么时候能救我一次"。
用户看不到价值 → 觉得"有没有都一样"。

## 三、逐个技能：后端怎么加强 · 前端怎么呈现

> 格式：**它是什么 → 后端现状 → 后端怎么加强 → 前端怎么呈现 → 判据**

### 1. 世界引擎 `world.py`（36 接口 · 最该被"用起来"的一个）
- **是什么**：长篇防漂移的根 —— 人物/地点/物品/组织，别名，事实（带证据），关系，时间线上的"时刻"
- **后端加强**：
  - 事实**带来源**（哪一章哪一句），前端能点回去原文
  - **冲突检测**：同一实体同一属性出现两个矛盾事实 → 标红
  - **自动抽取**：写完一章，**一键从正文里抽实体/事实**（现在要靠 AI 手动）
  - 时间线视图接口：按"书中时间"排序的**事件序列**（不是章节顺序）
- **前端呈现**：
  - **人物卡**：头像位（封面首字）+ 身份 + 关系网（谁是谁的谁）+ 最近出现章节
  - **时间线**：竖轴，每个"时刻"一个点，点开看那一幕
  - **冲突红点**：世界面板角标显示"有 N 处自相矛盾"，点进去逐条修

### 2. 伏笔账本 `plot.py` 的 promise
- **是什么**：埋了没回收的坑
- **后端加强**：**回收检测**（扫正文找"是否已回收"）+ **超期提醒**（埋了 N 章还没动）
- **前端呈现**：账本一行一条（埋在第X章 / 状态：待回收 / 超期 N 章 / [去回收]）；顶部一条统计
- **判据**：埋一条 → 超期天数/章节数能算出来

### 3. 大纲 `outline`（故事线点开就是它）
- **后端加强**：层级（主线/支线/章节细纲）+ **与正文的偏差检测**（写着写着偏了没）
- **前端呈现**：可折叠树 + 「用户手改的」标记 + AI 不许覆盖（**已有**）

### 4. 质检 AI 味 `lint.py`（565~568 条规则 · 最"有货"的一个）
- **后端加强**：规则**按维度**给分（比喻堆砌 / 排比 / 空泛形容词 / 破折号 / 口播腔…），
  **每个扣分点能点回原文**；**一键修**保留原意
- **前端呈现**：**评分环 + 分维度条**，下面按"扣分最多"排序的清单，每条带 `[看原文] [就这样] [改]`

### 5. 记忆 `rag.py` / `engine/memory.py`
- **后端加强**：**按章回填**（AI 写完自动记"这章发生了什么"）+ 检索带出处
- **前端呈现**：时间轴式"AI 记得的事"，**点一条能看到来源章节**；能手动纠错/删除

### 6. 人物声音 `engine/voice.py`(474)
- **是什么**：谁在说话，文字上分得出来（口头禅/称呼/句长/语气）
- **前端呈现**：每个主要人物一张"说话卡"（口头禅、称呼别人怎么叫、例句 3 条）
  + **一致性提醒**："这一章「小李」的叫法跟前面不一样"

### 7. 节奏/情绪曲线 `pacing.py`
- **前端呈现**：**折线图**（每章一个点：紧张/平淡/温情），下面标"连续 3 章都在吵架"
- **后端加强**：自动给每章打标（用模型），并给"该松一松了"的建议

### 8. 角色一致性 `engine/consistency.py`(254)
- **前端呈现**：体检报告式清单（外貌/年龄/称呼前后对不上），每条**并列两处原文**+`[统一成哪个]`

### 9. 多 Agent 编排 `orchestra.py`(835) + `agent_runtime.py`(828)
- **后端加强**：**每棒可视**（谁在干、干完给谁）、**失败能重试某一棒**、**成本可见**
- **前端呈现**：横向"棒次条"（1 主创 → 2 挑刺 → 3 主创 → 4 挑刺），**当前那棒高亮**，
  跑完在气泡下给"这一轮用了什么"卡片（**已有雏形**）

### 10. 联网搜索 `websearch.py`
- **前端呈现**：对话设置里的开关（**已有**）+ **搜到的样本先给用户看一眼再引用**

### 11. 听书 `tts.py`
- **后端没问题**（我实测过：72 段 / 4.5 秒 MP3 / 公网 200）
- **前端**：播放器 + 音色试听 + **听书自检**（已有）

### 12. 统计激励 `stats.py` + `calendar.py`
- **前端呈现**：日历热力图（今天写了多少）+ 进度曲线 + 成就墙；**日报/周报卡片**

### 13. 参考书架 `refs.py`
- **前端呈现**：图片/文件卡片墙 + 摘抄列表；**写作时能引用**（已有）

### 14. 流水线 `workflows.py`
- **前端呈现**：可视化步骤条（写 → 润色 → 质检 → 存），一键跑，**每步结果可回看**

## 四、后端"还能更好"的清单（按性价比排序）

1. **世界引擎加"一键从正文抽实体/事实"** —— 把 36 个接口真正用起来，价值最高
2. **质检分维度评分 + 扣分点可跳原文** —— 565 条规则现在是"一坨"，要拆开给人看
3. **伏笔回收检测 + 超期提醒** —— 后端算得出来，前端一个小红点就有用
4. **记忆按章自动回填** —— 现在是空的，填上立刻"有用"
5. **一致性体检 + 声音档案合到"体检"一个入口** —— 两个薄面板合成一个厚的
6. **编排每棒可视 + 单棒重试**
7. **动作接口加"幂等 + 可撤销"**（改动收件箱已有雏形，扩展到所有写操作）
8. **所有写操作都进审计日志**（`misc.py` 的 audit 已有表，前端给"撤销"按钮）

**统一原则**：**只增不减**；每个新能力都要有**能报红的判据**。

## 五、前端信息架构：28 个入口建议合成 **5 组 · 12 个**

| 组 | 保留的入口 | 合并进来的 |
|---|---|---|
| **写** | 写作台 · 故事线(大纲) · 章节顺序 | 常用指令、小批注入口 |

| **书稿** | 参考书架 · 素材 · 导出 · 统计 | 封面、笔记、书签 |
| **系统** | 数据(备份+同步+日志) · 关于 | 账号、改动、听书(挪去阅读器) |

**判据**：合并后每个入口点进去**至少 3 屏内容**；空的合并掉。
