## 2.7.7 · 破限层（每个角色一份）+ 修两个真 bug

### 破限层：让 AI 以「作者本人」的身份写

模型默认带着一层自我审查：写亲密戏会淡出、写暴力会绕开、张口就是「我不能写这个」。
可这是**你自己的小说**，它没理由替你踩刹车。

现在每个角色都带一份**专属于自己的**放开立场：
- **写手** → 亲密、暴力、重口场面直接写透，不许用比喻绕开
- **主创** → 讨论剧情时该露骨就露骨，不许用「发生了一些事」含糊过去
- **挑刺** → 该露骨的地方写含糊了要**直接指出来、要求重写**；不许把「太放开」当问题
- **润色** → 不许把露骨处改含蓄（只许改病句水词）
- **查证 / 取上下文** → 不给（它们是查资料的，给了反而添乱）

**为什么每个角色只给一份**：给所有人塞同一套没用 —— 挑刺拿到「放开写」只会说「写得挺好」。

**在哪里改**：设置 → 预设 → 「写作者立场（破限）」开/关，以及「立场细则」那个输入框。
留空就用内置的；**想加强就写得更狠更具体**（比如列清楚你不接受它说哪几句话）。

### 两个 bug

- **主创「一个字没说」**：它其实写了四千多字，但中间夹满了模型等工具结果时自己念的
  「空出这一行以等待工具执行结果。call:xxx {}」——把正经话全盖住了。
  现在组装「给你看的那份」时整行丢掉（工具记录一个字没少）。
- **「讨论/计划不许写文件」有漏洞**：规则里只写了 `write_file` 一个名字，
  而工具清单里还有 `outline_write`（写大纲）—— 它漏网了。
  现在按 `{write_file, outline_write}` 集合判断，并在源头注明「以后再加写类工具必须往这里补」。

## 2.7.6 · App 从 26.2MB 缩到 0.47MB

**以前**：包里塞了一整套 Python 运行时（三种 CPU 架构各一份）+ 30 多个 Python 库，
未压缩约 31MB，而真正要用的前端只有 1MB —— 这个包 98% 是废的。

**为什么**：这些是早年"把后端也装进 App"那个方案的遗留。方案后来作废了
（后端只跑在服务器上，App 就是纯前端），但行李一直没扔。因为它是**关着**的、
不跑就不出错，所以每次都在修别的问题，一直没动它。

**现在**：整套 Python 运行时从包里拿掉了。
- 包体积 **26.2MB → 0.47MB**，下载和安装都快得多
- "App 连到自己的空后端、界面看着正常其实什么都没有"这类问题，
  从根上不可能再发生

> 顺带说明：本机那条 Python 路径的代码还在（默认不执行），用两个空壳类让它照常编译过 ——
> 直接删要动很多逻辑、风险大。以后彻底清理时把它们一起删掉即可。

## 2.7.5 · 治好卡顿

**以前**：App 里点一下、滑一下，总有一点说不出的延迟，不如老版跟手。

**为什么**：老版 App 的页面是**从服务器加载**的，前端用 `fetch()` 发请求 ——
**异步，发出去就走，界面不等**。新版改成"把界面打进安装包"之后，为了绕开
`file://` 页面的跨源限制，把所有接口请求都塞进了一个 Java 桥，而**桥是同步调用**：
JS 必须停下来等 Java 把 HTTP 发完再回话。公网上一个来回几百毫秒，
界面就跟着卡几百毫秒 —— 每次请求卡一下。

**现在**：接口请求全部改回异步 `fetch`（WebView 已经开了跨源、服务器也给了 CORS），
桥只留给"必须同步拿值"的小事（版本号、震动、下载、存口令）。

## 2.7.4 · 治好"每次打开都要重新输密码"

**以前**：每次打开 App 都要输一遍登录口令。

**为什么**：老版 App 是从服务器加载页面的，登录凭证由 WebView 自己保管、重启还在；
新版改成从安装包里加载（`file://`）之后，安卓对这种页面**不保留 cookie 和本地存储**，
凭证存不住，于是每次都要重输。

**现在**：登录成功后把口令存进手机（`SharedPreferences`），
每次启动**静默登录**一次 —— 用户根本看不到登录页。
（令牌存盘那条路保留，双保险。）

## 2.7.2 · 网页里就能更新

**以前**：出了新版要登服务器敲命令才更得上。

**现在**：**设置 → 关于 → 更新 → 检查更新 → 立即更新**。
前端和后端在同一个端口上，所以重启一次两边都生效。
（国内直连 GitHub 常超时，会自动走本机代理。）

> 注意：已经部署过的老实例，**第一次**还是要手动
> `git pull && systemctl --user restart novelapp` 把"一键更新"这个功能拉下来；
> 之后就能一直用网页里的按钮了。

## 2.7.1 · 一串小毛病

- **口令「复制」点了没反应** —— 浏览器的新剪贴板接口只在 `https` 下可用，
  而这个服务通常是 `http://` 访问的。改用哪儿都能用的老办法。
- **设置页最下面的说明文字被裁掉**（穿模）—— 那段文字原本放在一张
  `overflow:hidden` 的卡片里。挪到卡片外面。
- **同一批接口被重复请求 3 遍** —— 同一个请求还在路上时，第二个调用不再重发，
  直接等第一个的结果；写完数据立刻让缓存失效，不会看到旧数据。

## 2.7.0 · 大版本

- **模型参数**：每个模型右上角「⋯」可调上下文上限（1M / 256K / 128K…）、
  单次最大输出、是否推理模型，以及一段直接并进请求体的高级参数 JSON。
- **干活方式三种 × 两种**：讨论 / 计划 / 执行，每一种都能选「多 Agent 分工」或
  「一个人从头做到尾」。
- **联网搜索**：默认关闭，对话框旁边一枚开关；关闭时一个请求都不发。
- **新书不再直接跳到第二章**：最新章节为空时先写那一章。
- **开源发布**：AGPL-3.0、README、requirements.txt、空白通用版 APK。

### 另外修掉一个"别人装完根本起不来"的坑

仓库缺少 `python-multipart`（FastAPI 的 `Form`/`File` 隐式依赖，
静态扫 import 扫不出来）。照文档装完依赖、一启动就
`RuntimeError: Form data requires "python-multipart"` —— 整个服务起不来。
已补上，并加了 `tools/check_deps.py` 做依赖自检，防止再漏。

## 2.8.0

- **「一个人（全套）」下面按步骤分开设置**。原来 7 步共用一份设置 = 每一步都调不了。
  现在按「戴哪顶帽子」分成 5 组，每组一栏：
  ① 主创那几步（排计划 / 出主张 / 回应与收敛 / 定稿 / 汇总）
  ② 取上下文那一步 ③ 查证那一步
  ④ 写正文那两步（写初稿 / 按批注改稿） ⑤ 挑刺那一步
- 走到那一步，就把那一栏写的话**拼进这一步的要求里**（实测：第 1/7 步带主创的、
  第 4/6 步带写手的、第 5 步带挑刺的）。
- 分工模式完全不受影响（仍是讨论 4 / 计划 4 / 执行 7 棒）。
